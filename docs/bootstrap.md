# 引导链路细节

规则（nix 配置归属、mkForce 边界、token 存放）在 [`AGENTS.md`](../AGENTS.md)「Nix configuration ownership and bootstrap」；本文承载三条链路的运作细节。内容系 2026-09-28 从 AGENTS.md 对应子弹拆出（拆分记录见 [`VALIDATION.md`](VALIDATION.md)），措辞以搬运为主。

## 统一入口 bootstrap/bootstrap.sh

`bootstrap/bootstrap.sh` is the **unified auto-detecting entry**: Darwin → `darwin.sh`; Linux with `/etc/NIXOS` → `nixos.sh` (re-exec'd via sudo when not root; mode/target still self-detected there); other Linux → `linux.sh` with the arch-derived default target. It carries the same outside-the-repo `CLONE_DIR` self-fetch as the sub-scripts, rejects WSL1 (kernel name without `microsoft-standard`) and unknown architectures up front, and prints an informational note for non-bash login shells. All three sub-scripts remain directly runnable; the entry only detects and dispatches, keeping detection logic duplicated (deliberately) with the sub-scripts' own guards. All three chains also tee their entire run to a timestamped log under `${XDG_STATE_HOME:-$HOME/.local/state}/nix-roam/` (`linux-*` / `darwin-*` / `nixos-*`), attached after the self-fetch re-exec so one-liner runs log at the final location too; `nixos.sh` runs as root, so its logs live under `/root/...`. Token input goes through stdin and never enters a log; the dispatcher itself does not wrap a tee (it execs into a sub-script immediately).

## bootstrap/linux.sh（普通 Linux / WSL，七步）

`bootstrap/linux.sh [target]` is for ordinary Linux/WSL and runs seven steps: install Nix, configure mirrors, optionally store a GitHub token, enable flakes, back up conflicting files, install Home Manager, activate with `-b backup`. Step 7 ends with a fail-loud PATH self-check: a clean-environment `/bin/bash -lc` must still resolve `nix` after activation (guards the single-user dotfile-hook loss fixed by `home/standalone-linux.nix`'s sessionPath entry; zsh/fish interactive-only appends are out of its scope). Do not use it for NixOS-WSL or for macOS. The default target is the arch-named standalone output (`x86_64-linux` on x86_64, `aarch64-linux` on aarch64; other architectures abort; an explicitly passed target must match the local arch, fail-loud). It rejects WSL1.

Nix installation has two modes (`NIX_INSTALL_MODE=multi|single|auto`, default auto): `multi` (systemd present and `sudo -v` works) uses the Determinate Systems installer and writes daemon-side mirror trust to `/etc/nix`; `single` (no systemd or no sudo — also covers non-systemd distros like Artix/Devuan/Void) uses the official installer `--no-daemon` and writes mirrors to the user-level `~/.config/nix/nix.conf` plus an exported `NIX_CONFIG` for the session. The `/nix` prefix still requires one-time root creation (and an existing non-writable `/nix` a one-time owner fix), performed by the `run_as_root` front end: `sudo` when present, otherwise interactive `su -c` (root password; `su_root` %q-escapes each argument into the single `-c` string — the branch requires a tty on stdin, which `bash <(curl …)` preserves and `curl | bash` cannot offer), covering username-valid-but-no-sudo minimal distros/WSL (e.g. Gentoo WSL) without admin help; when neither path works the script prints the exact manual command (with the WSL `wsl -d <distro> -u root` entry hint) instead of half-configuring. Steps 3/4 (token include, flakes) skip appends when the user `nix.conf` is already an HM-owned symlink, matching `darwin.sh`.

The username guard compares the `meta.json` `username` directly with `id -un` (extraction failure aborts — no hardcoded fallback). An already-existing configured user → "log in as it and rerun" (existing accounts are never touched; root gets a `su -l` hint). On an interactive terminal with privilege — root itself, or non-root with working sudo — the script offers to create the configured system user and continue as it: `useradd -m`, interactive `passwd`, best-effort sudo/wheel group membership (skipped with a note when no sudo binary exists), repo copied into the new user's home (root: `cp -a` + `chown -R`; read-only fallback to the current checkout), then re-exec as that user — standalone's counterpart of the NixOS side provisioning `users.users.<username>` via the flake. Non-root re-execs via `sudo --login`; root via `su --login <user> -c '<one %q-quoted string>'` with `runuser --login -c` as fallback — `su` is primary because its PAM stack is plain `pam_unix`, while `runuser`'s `session include system-login` drags in pam_systemd and was observed hanging on a wedged WSL logind (ArchLinux-WSL, 2026-09-24); util-linux's multi-argv `-- CMD ARGS` form is broken on both tools anyway (`cannot execute binary file`, Fedora/Arch), hence the single `-c` string. Root without a sudo binary additionally pre-creates `/nix` (0755, owned by the new user) so the re-run lands in single-user install. Declining, non-interactive or privilege-less keeps the fail-loud abort with the `meta.json` hint.

In WSL the create-user flow then asks whether to make the new user the WSL default (`[Y/n]`): consent merges `[user] default=<username>` into `/etc/wsl.conf` via `wsl_conf_merge()` — a pure-bash merge (gawk cannot be assumed: the author's own Fedora WSL ships without it) that preserves existing sections/keys, writes a timestamped backup of the original, and only warns on failure (a cosmetic setting never aborts the install); declining keeps the manual hint.

It also runs outside a checkout (the README curl one-liner or a standalone downloaded copy): it fetches the repo to `CLONE_DIR` (default `~/nix-roam`, overridable; git clone preferred, Gitee archive tarball when git is missing) and re-execs the in-repo copy. Both standalone bootstraps resolve a username mismatch before touching any system nix setting (standalone Home Manager can only activate for the current user) — abort with the one-line `meta.json` hint, or the interactive create-user offer above (`darwin.sh` uses `sysadminctl -addUser … -admin -password prompt`; that branch is stub-verified only, never run on real macOS) — preventing the half-configured state of system nix settings being rewritten before activation fails on someone else's HOME.

## bootstrap/darwin.sh（macOS，Apple Silicon）

`bootstrap/darwin.sh [target]` is the macOS counterpart, defaulting to `<meta.json username>-darwin` (same extraction pattern as the other scripts, fail-loud): same seven steps and Determinate Systems installer, guarded to Apple Silicon (`uname -s` = Darwin and `uname -m` = arm64; Intel Macs are rejected because the flake only outputs aarch64-darwin). It supports the same outside-the-repo one-liner and `CLONE_DIR` self-fetch as `linux.sh`. macOS differences: in-place edits use BSD `sed -i ''`; user-level `nix.conf` appends (token include, `experimental-features`) are skipped when the file is already a Home Manager-owned symlink — the token include is carried by `home/standalone-darwin.nix`'s `nix.extraOptions`, flakes by `nix-cn.nix`. It installs no nix-darwin and manages no system services or GUI; it has not yet been run on a real macOS host. macOS conventions are preserved: the default shell stays zsh, `~/.zshrc` is never taken over (only the guarded hm-session-vars append described in AGENTS.md's Home Manager layout), and Homebrew coexists with nix paths taking PATH precedence.

## bootstrap/nixos.sh（install / adopt）

`bootstrap/nixos.sh [install|adopt] [--target <hostname>]` bootstraps the NixOS side and must run as root. `install` runs inside the live ISO with the target mounted at `/mnt` — partitioning/formatting is deliberately out of scope (reference commands live in the script header); `adopt` runs on an installed NixOS or a freshly imported NixOS-WSL. Mode is auto-detected via `/etc/NIXOS`, target via the WSL kernel marker; WSL has no `install` chain. `--target` accepts any `[a-zA-Z0-9-]` hostname: when `hosts/<target>/` is missing, the script scaffolds it from `hosts/_template/` (replacing `__HOSTNAME__`), prints paste-ready desktop/CLI flake output blocks, waits for the manual `flake.nix` paste and verifies the output exists before continuing — it never edits `flake.nix` itself. `install` re-runs `nixos-generate-config --root /mnt` every time, moves the result into `hosts/<target>/hardware-configuration.nix` (previous copy backed up alongside with a timestamp — commit the regenerated file back to Gitee), requires a `/boot` entry (systemd-boot) and sets the configured user's password via `nixos-enter` because the flake defines no password fields (the username is read from `meta.json`'s single-point `username`; extraction failure aborts — the old `xuqihao` fallback is gone). `adopt` backs up a foreign `/etc/nixos` wholesale and aborts on a stateVersion mismatch unless explicitly confirmed.

Mirrors/token are bootstrap-time only, delivered daemon-side through `/etc/nix/nix.custom.conf` plus an exported `NIX_CONFIG` — an `nix.settings`-managed `/etc/nix/nix.conf` is a store symlink that cannot be appended to; after adoption `modules/fix-network.nix` → `home/nix-cn.nix` takes over as the single source. The adopt chain had its first live run 2026-09-24 on NixOS-WSL (dispatcher → sudo re-exec → adopt → `.#wsl` switch; steps 1–5 verified, `home-manager-xuqihao` activated): switch-to-configuration returned exit 4 from the recurring host-side WSL cgroup fault (dead `user@1000.service`, same as 2026-09-19 — remedied by Windows-side `wsl --shutdown`, fresh boot loads the new generation's user units directly), and `set -euo pipefail` aborted the script before the informational 6–7/7 steps although activation had succeeded. The install chain (live ISO) has not been exercised on real hardware yet.
